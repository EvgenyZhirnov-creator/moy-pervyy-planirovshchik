# Концепция проекта «Планировщик продаж ИСП»

## 1. Назначение

Мобильный планировщик помогает сотруднику организовать рабочую неделю с понедельника по пятницу, вести встречи и продажи инвестиционных продуктов, видеть выполнение плана и прогноз результата к концу недели.

На первом экране сотрудник должен быстро получить ответы на вопросы:

- Какой план установлен по каждому продукту?
- Сколько уже продано и сколько комиссионного дохода получено?
- Сколько осталось до выполнения плана?
- Какой результат ожидается по запланированным встречам?
- Какие действия и встречи запланированы на сегодня?

Проект состоит из трёх файлов: `index.html`, `style.css` и `script.js`. Данные хранятся в браузере через localStorage. Базы данных, серверная часть, внешние сервисы и обязательные библиотеки не используются. Этот документ описывает будущую реализацию; файлы страницы на этапе концепции не создаются.

## 2. Продукты и первоначальная настройка

Перечень продуктов фиксирован:

| Сокращение | Название |
| --- | --- |
| ОПИФ | Открытые паевые фонды |
| ЗПИФ | Закрытые паевые фонды |
| ИСЖ | Инвестиционное страхование жизни |
| НСЖ | Накопительное страхование жизни |
| РДУ | Доверительное управление |

При первом запуске сотрудник указывает своё имя или внутренний идентификатор и задаёт фиксированный процент комиссии для каждого продукта. Названия и проценты после завершения первоначальной настройки не редактируются в обычной работе. Проценты необходимо получить от пользователя перед реализацией либо оставить для однократного ввода при запуске. Выдуманные ставки не используются.

По умолчанию все суммы отображаются в рублях. Денежные расчёты выполняются с точностью до копейки; на карточках большие суммы могут сокращаться до тысяч или миллионов рублей с возможностью увидеть полное значение.

## 3. Недельный план и показатели

Сотрудник выбирает неделю и вручную вводит для каждого продукта:

- План объёма продаж в рублях.
- План комиссионного дохода в рублях.

Оба показателя сохраняются отдельно. При вводе плана объёма интерфейс предлагает комиссионный план, рассчитанный по ставке продукта. Сотрудник может принять предложенное значение или указать своё. Если ручной план дохода отличается от расчётного, интерфейс показывает это различие.

Неделя охватывает понедельник–пятницу включительно. Выходные не входят в расчёт недельных показателей. Новая неделя начинается с пустого плана; доступно явное действие «Скопировать план прошлой недели».

Для каждого продукта рассчитываются объём и комиссионный доход:

| Показатель | Правило расчёта |
| --- | --- |
| Факт | Сумма зарегистрированных продаж выбранной недели |
| Выполнение | Факт / план × 100% |
| Осталось до плана | Максимум из «план − факт» и нуля |
| Прогноз | Факт + ожидаемый результат актуальных запланированных встреч |
| Прогнозный дефицит | Максимум из «план − прогноз» и нуля |
| Фактическое перевыполнение | Максимум из «факт − план» и нуля |
| Прогнозное превышение плана | Максимум из «прогноз − план» и нуля |

Перевыполнение показывается отдельным положительным результатом. Числовой процент выполнения может превышать 100%, а полоса прогресса заполняется до 100%.

Если план не задан или равен нулю, процент выполнения не рассчитывается и выводится «План не задан». Факт и прогноз при этом остаются видимыми. Отсутствие плана не считается достижением цели.

Общие показатели недели складываются из показателей пяти продуктов. История планов, встреч и продаж сохраняется для прошлых недель.

## 4. Продажи и прогноз

### Фактические продажи

Каждая продажа записывается отдельно. Обязательные поля: дата, ID клиента, продукт и сумма. ID клиента хранится как текст, чтобы сохранять ведущие нули. Сумма должна быть положительной.

Комиссионный доход рассчитывается автоматически:

**Комиссионный доход = сумма продажи × процент комиссии продукта / 100.**

Продажу можно добавить из встречи или отдельно. Если продажа относится к встрече, сохраняется связь с конкретным продуктом этой встречи. Проведение встречи само по себе не создаёт продажу и не увеличивает факт.

Исправление или удаление продажи пересчитывает показатели соответствующей недели. Исторический просмотр показывает сохранённые данные, а не заменяет их данными текущей недели.

### Прогноз к концу недели

Прогноз рассчитывается по полному ожидаемому объёму актуальных запланированных продаж. Вероятности сделок и коэффициенты не применяются: пользователь выбрал прогноз по запланированным встречам и объёмам.

Каждая встреча содержит одну или несколько строк продуктов. В строке задаются продукт и ожидаемая сумма. Комиссионный доход по строке рассчитывается по фиксированной ставке продукта.

В прогноз текущей недели включаются встречи со статусом «Запланирована», датой от сегодняшнего дня до пятницы включительно и ненулевым оставшимся ожидаемым объёмом. Встречи на сегодня учитываются до обновления их статуса, даже если время встречи уже прошло.

Правила предотвращения двойного учёта:

- Если по строке встречи уже зарегистрирована связанная продажа, ожидаемый остаток равен максимуму из «ожидаемая сумма − связанные фактические продажи» и нуля.
- Фактическая продажа входит в факт по дате продажи. Ожидаемый остаток относится к неделе даты встречи.
- Встречи со статусом «Проведена» или «Отменена» не добавляют ожидаемый результат к прогнозу. Их реальные продажи учитываются отдельно.
- При переносе встреча сохраняет свой идентификатор и получает новую дату. Старая дата остаётся в истории переноса, но не создаёт вторую активную встречу.
- После назначения новой даты перенесённая встреча получает статус «Запланирована» с отметкой о переносе. Статус «Перенесена» без новой даты означает, что встречу нужно перепланировать; её объём не включается в прогноз.
- Просроченные встречи прошлых дней с незавершённым статусом показываются отдельным списком «Требуют обновления» и не увеличивают прогноз текущей недели до перепланирования.

Пример: план ОПИФ — 5 млн ₽, факт — 2 млн ₽, ожидаемый остаток продаж на встречах — 2,5 млн ₽. Прогноз составляет 4,5 млн ₽, остаток до плана по факту — 3 млн ₽, прогнозный дефицит — 500 тыс. ₽. При условной комиссии 1% фактический доход равен 20 тыс. ₽, прогнозный — 45 тыс. ₽. Ставка в примере служит только для объяснения формулы.

Прогноз не является гарантией продажи. На экране он подписан как результат «По запланированным встречам». Для будущих недель используется факт выбранной недели и её активные запланированные встречи. Для завершённых недель отображаются итоговые фактические показатели и сохранившиеся невыполненные встречи без представления их объёма как будущего результата.

## 5. Календарь и целевой тайминг

Основной вид на телефоне — выбранный день. Над расписанием располагается компактная полоса понедельник–пятница с датами и количеством встреч. Переключение дней доступно одним нажатием. Дополнительный вид «Неделя» показывает пять дней последовательно, без обязательной горизонтальной прокрутки.

Карточка встречи содержит:

- Дату и время начала.
- ID клиента.
- Один или несколько продуктов с ожидаемыми суммами.
- Статус: «Запланирована», «Проведена», «Перенесена» или «Отменена».
- Заметки.

Длительность не была указана пользователем как обязательное поле. Для размещения на временной шкале принимается рабочее допущение: продолжительность по умолчанию 30 минут с возможностью изменить время окончания встречи.

Сотрудник самостоятельно создаёт целевой тайминг: рабочие часы, обед и блоки действий с временем начала и окончания. Например, проверка почты, обзвон клиентов, встречи, оформление продаж и подведение итогов.

Можно настроить отдельный шаблон для каждого рабочего дня, повторять его по неделям и изменять расписание конкретной даты. Изменение шаблона не переписывает историю прошедших дней.

Встречи отображаются поверх целевых блоков или внутри них. Попадание встречи в блок «Встречи с клиентами» считается ожидаемым. Пересечение двух встреч или попадание встречи в обед либо другое занятие отмечается в интерфейсе, но сотрудник может сохранить расписание после просмотра пересечения.

Основные действия в календаре: добавить встречу, открыть подробности, изменить статус, перенести, записать продажу и отредактировать тайминг. Перетаскивание не обязательно: все действия доступны через формы и кнопки на телефоне.

## 6. Главный экран и оформление

Главный экран строится для телефона, сверху вниз:

1. Имя сотрудника, выбранная неделя и переключение недель.
2. Крупные общие показатели: прогноз объёма продаж и прогноз комиссионного дохода.
3. Карточки пяти продуктов с крупным прогнозом объёма и дохода, планом, фактом, процентами выполнения и двумя видами дефицита.
4. Расписание выбранного дня и ближайшая встреча.
5. Незавершённые встречи, требующие обновления, если они есть.

На карточках явно различаются факт, прогноз и план. Для каждого продукта доступны две полосы прогресса: объём продаж и комиссионный доход. Расчёты обновляются сразу после изменения плана, встречи или продажи.

Нижняя навигация: «Обзор», «Календарь», «Продажи», «Настройки». История доступна через выбор недели. Основные формы открываются в удобных для телефона панелях; подписи полей остаются видимыми при вводе.

Визуальный стиль: светлый фон, глубокий фиолетовый для основных элементов, светлые фиолетовые оттенки для выделения, строгая типографика и умеренное скругление карточек. Зелёный обозначает достижение и перевыполнение, янтарный — дефицит и необходимость внимания. Состояния сопровождаются текстом и не зависят только от цвета.

Кнопки достаточно крупные для нажатия пальцем. Основной сценарий работает на узком экране без горизонтальной прокрутки. Интерфейс адаптируется и к компьютеру.

## 7. Мотивация

Награда привязана к выполнению недельного плана отдельного продукта.

Рабочее правило достижения цели: по продукту установлены положительные планы объёма и комиссионного дохода, и оба фактических показателя достигли 100% или выше. Прогнозное достижение цели не запускает награду.

При первом достижении цели появляется короткая сдержанная анимация в фирменных цветах и сообщение «Цель достигнута — [продукт]». Карточка получает значок достижения, который сохраняется в истории недели. За каждый продукт предусмотрена отдельная отметка.

Анимация воспроизводится один раз для пары «неделя + продукт» и не повторяется после обновления страницы. Если продажу исправили и факт стал ниже плана, актуальная отметка выполнения снимается; повторная анимация на этой неделе не запускается. Учитывается настройка уменьшения движения в браузере.

Сообщения о дефиците остаются деловыми: «До цели осталось 450 000 ₽» или «По встречам ожидается выполнение 92%». Мотивация помогает видеть следующий шаг без давления и обещаний реальных премий.

## 8. Сотрудник и руководитель

Пользователь запросил персональный планировщик сотрудника и доступ руководителя к планировщикам сотрудников. При хранении только в localStorage данные находятся в конкретном браузере на конкретном устройстве. Автоматический доступ руководителя с другого устройства и общая актуальная база недоступны в заданной архитектуре.

Предлагаемое решение для первой версии — обмен файлами:

- Сотрудник экспортирует данные в JSON-файл и самостоятельно передаёт его руководителю.
- Руководитель импортирует файл в режим просмотра сотрудников этой же страницы.
- Каждый импорт относится к конкретному идентификатору сотрудника. Повторный импорт обновляет его снимок после проверки файла и подтверждения замены.
- Руководитель видит список сотрудников, планы, фактические продажи, прогнозы и календари из полученных снимков.
- У каждого снимка видны дата экспорта и дата импорта. Новые продажи сотрудника появятся у руководителя после следующего обмена файлами.
- Представление руководителя предназначено для просмотра. Переключение режима в локальной странице не является системой авторизации или разграничением прав доступа.

Ручной обмен снимками через экспорт и импорт согласован пользователем. Руководитель просматривает данные на момент последнего полученного экспорта. Если в дальнейшем понадобится автоматический доступ к актуальным данным, потребуется пересмотреть требование «без серверов и общей базы» и выбрать способ синхронизации.

## 9. Хранение и проверка данных

В localStorage сохраняются настройки сотрудника, фиксированные ставки продуктов, планы по неделям, продажи, встречи и история переносов, шаблоны тайминга, изменения конкретных дней, отметки достижений и импортированные снимки сотрудников.

Записи имеют уникальные идентификаторы. Файл экспорта содержит версию формата данных. Даты рабочего календаря хранятся как локальные календарные даты, чтобы встреча не смещалась на другой день при обработке времени.

Данные сохраняются после каждого успешного изменения и восстанавливаются при следующем открытии. При ошибке сохранения интерфейс сообщает об этом и не показывает ложное подтверждение. При импорте проверяются структура файла, продукты, даты, суммы и обязательные поля. Ошибка импорта не заменяет текущие данные.

Резервное копирование и восстановление доступны в настройках. Перед заменой имеющихся данных показывается, что будет заменено. Очистка данных требует явного подтверждения. ID клиента используется без обязательного ввода имени, телефона и других персональных сведений.

История остаётся доступной, пока сохранены данные браузера или резервная копия. Переход на другое устройство сам по себе не переносит localStorage.

## 10. Условия готовности первой версии

- Созданы только три файла страницы: HTML, CSS и JS.
- Планировщик удобен на телефоне и работает без серверной части.
- Учитываются все пять фиксированных продуктов и их ставки комиссий.
- План, факт, дефицит, прогноз и перевыполнение рассчитываются отдельно по объёму и доходу.
- Прогноз строится по ожидаемым продажам активных встреч, включая встречи с несколькими продуктами, без двойного учёта связанных продаж.
- Календарь поддерживает пользовательский тайминг и четыре статуса встреч.
- Каждая продажа содержит дату, ID клиента, продукт и сумму.
- Данные и история недель сохраняются после перезагрузки страницы.
- Достижение плана продукта сопровождается однократной анимацией и отметкой в истории.
- Экспорт и импорт восстанавливают данные без потери связей продаж и встреч.
- Способ доступа руководителя согласован с ограничениями выбранной архитектуры.

Способ доступа руководителя согласован: экспорт сотрудником и импорт руководителем. Проценты комиссий можно предоставить заранее или заполнить при первом запуске. Остальные неуказанные детали в документе являются предложенными рабочими решениями, которые можно скорректировать перед реализацией. Создание HTML, CSS и JS выполняется после отдельного поручения пользователя.
